# Словарь предметной области

Канонический глоссарий проекта «Склад» — [`_hubx01/GLOSSARY.md`](../../../_hubx01/GLOSSARY.md):
там полный маппинг «бизнес-термин → таблица БД → URL `SkladApi` → JSON-ключи → модель UI».
Этот файл — краткая выжимка для фронтенда `apps/skladX01_v0` в том же формате.
При расхождении прав канон в хабе, здесь — только то, что нужно в коде и шаблонах.

## 1. Сущности (БД → API → UI)

| Бизнес-термин | Таблица / поле в БД (`Sklad-v4.1`) | URL в `SkladApi` | JSON-ключи (camelCase кириллица) | Модель UI (латиница) |
|---|---|---|---|---|
| **Клиент** | `Клиент` (`Id`, уникальный `Псевдоним`) | `/api/clients` | `id`, `псевдоним`, `фио`, `телефон`, `город`, `пределКредита`, `активен` | `IClient`: `id`, `alias`, `fullName`, `phone`, `city`, `creditLimit`, `active` |
| **Сводка по клиенту** | `vw_БалансСделки` | `/api/clients/{id}/summary` | `клиентId`, `псевдоним`, `пределКредита`, `активен`, `сделок`, `активныхСделок`, `отгружено`, `оплачено`, `долг`, `переплата`, `превышенЛимит` | `IClientSummary`: `clientId`, `alias`, `creditLimit`, `active`, `deals`, `activeDeals`, `shipped`, `paid`, `debt`, `overpayment`, `limitExceeded` |
| **Сделка** *(устар. «Метка»)* | `Сделка` (`КодСделки`, `НомерСделки`) | `/api/clients/{id}/marks` | `id` (Guid), `номер`, `долг`, `комментарий` | `IMark`: `id`, `number`, `debt`, `comment` |
| **Накладная / Отгрузка** | `НакладнаяРасход` + `Расход` | `/api/clients/marks/{dealId}/products` | `id`, `номер`, `дата`, `сумма`, `сделкаId` | `IShippedGood`: `id`, `number`, `date`, `amount`, `dealId` |
| **Оплата / Деньги** | `Деньги` | `/api/clients/marks/{dealId}/payments` | `id`, `дата`, `сумма`, `сделкаId` | `IPayment`: `id`, `date`, `amount`, `dealId` |
| **Поставщик** | `Поставщик` | `/api/suppliers`, `/api/suppliers/{id}` | `id`, `название`, `город`, `телефон` | `ISupplier`: `id`, `name`, `city`, `phone` |
| **Номенклатура** | `Номенклатура`, `ЕдИзмерения` | `/api/nomenclature` (+ `quick-search`, `candidates`, `references`) | quick: `id`, `код`, `артикул`, `название`, `едИзм`, `ценаЗакупочная`, `ценаПродажная` | `INomenclatureQuick`: `id`, `code`, `article`, `name`, `unit`, `purchasePrice`, `salePrice` |
| **Склад** | `Склад` | `/api/warehouses` | `id`, `название`, `псевдоним` | `IWarehouse`: `id`, `name`, `alias` |

## 2. Идентификаторы и ключи

- **`dealId` / `сделкаId`** — идентификатор сделки (`Guid`, `Сделка.КодСделки`); в URL `markId` не используется.
- **`НомерСделки`** — человекочитаемый номер `R-000151`, выдаётся `seq_НомерСделки` через DEFAULT.
- **`LegacyId`** — номер метки в эталоне `Sh_29-06-25`; только аудит переноса, в API не используется.
- **`UETR`** — идентификатор накладной из эталона, перенесён без изменений (`НакладнаяРасход.UETR`).
- **«Метка расчёта»** — устаревшее название сделки, осталось только в исторических именах (`МеткаРасчетDto`).

## 3. Правила именования

- В API и UI сделка называется сделкой: `dealId`, `сделкаId`, `КодСделки`.
- В шаблонах Angular — только латиница (`{{ client.alias }}`): кириллица даёт `NG5002`.
- Кириллические ключи JSON приходят в camelCase: `псевдоним`, `сделкаId`, `пределКредита`; маппинг в латиницу — в сервисах `apps/skladX01_v0/src/app/*/*.service.ts`.
- Остатков на складе в API нет: `nomenclature` — это справочник товаров, не `stock`/`balance`.
