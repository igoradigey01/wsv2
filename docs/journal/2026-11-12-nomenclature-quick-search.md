# 2026-11-12 — `skladX01_v0`: клавиатурный поиск номенклатуры и быстрое создание

## Что сделано

Разделены два поиска номенклатуры, которые раньше были одним эндпоинтом:

| Ввод | Эндпоинт | Механика |
|---|---|---|
| клавиатура (накладная, приход) | `GET /api/nomenclature/quick-search` | SQL LIKE по `Код/Артикул/Название`, `TOP 15`, без Ollama |
| голос («Заполнить по тексту») | `GET /api/nomenclature/candidates` | вектор + Левенштейн (не менялся) |

### API (`SkladApi`)

- `Dtos/НоменклатураQuickDtos.cs` — `НоменклатураQuickDto`, `СправочникDto`,
  `НоменклатураReferencesDto`, `ХарактеристикаВидаDto`, `СоздатьНоменклатуруRequest`.
- `НоменклатураRepository`: `QuickSearchAsync` (экранирование `% _ [ \` через
  `ESCAPE '\'`), `GetReferencesAsync`, `GetCharacteristicsAsync`, `CreateAsync`
  (транзакция `Номенклатура` + `ЗначениеХарактеристики`).
- `NomenclatureController`: `quick-search`, `references`, `kinds/{видId}/characteristics`,
  `POST /api/nomenclature` — 400 (пустые поля, тип вне 1..3, отрицательные цены,
  характеристики не из вида, значение вне диапазона/не из списка), 409 — дубль кода
  (`SqlException` 2601/2627).

### Фронт (`apps/skladX01_v0`)

- `nomenclature/nomenclature.service.ts` — клиент quick-search, справочников,
  характеристик и создания; маппинг кириллицы API в латинские поля моделей.
- `nomenclature/quick-create-item.component.*` — модалка «Быстрое создание»:
  справочники, динамические характеристики по виду (`List/Number/Text/Bool`),
  обязательные поля, ошибки API, «Сохранить и выбрать» отдаёт позицию в строку.
- `suppliers/receipt-page.component.*` — вместо `<select>` с кандидатами:
  таблица-подсказка (Код | Артикул | Название | Ед | Цена), ↑/↓, Enter — первая
  строка, Esc — закрыть, клик вне — закрыть; строка «➕ Создать новую…» открывает
  модалку; после создания позиция подставляется в строку вместе с ценой и ед.
- `invoice/invoice-page.component.*` — то же клавиатурное поведение в строках
  накладной; `candidates` остались отдельным `select` для голосового разбора.
- Общие стили подсказок (`.suggest*`, `.mono`) вынесены в `src/styles.scss`,
  чтобы не дублировать ~1.1 kB в двух компонентах и не пробивать бюджет 4 kB.

```
nx run skladX01_v0:lint         — OK
nx run skladX01_v0:build        — OK (без предупреждений о бюджете)
nx run skladX01_v0:test         — 10 наборов / 36 тестов
```

Тестовая позиция `ТЕСТ-QUICK-01` удалена из рабочей БД (2 значения характеристик
и сама номенклатура), проверка `Код LIKE N'ТЕСТ-%'` — пусто.

## Решения

- `POST /api/nomenclature` без хранимой процедуры: Dapper + транзакция, `Guid`
  и `ДатаСоздания` — DEFAULT-ы БД.
- Характеристики валидируются на сервере по данным вида, а не по тому, что прислал
  клиент: чужие `ХарактеристикаId` отклоняются.
- В приходе цена берётся из `ЦенаЗакупочная`, в накладной — из `ЦенаПродажная`
  (с фолбэком на вторую).
