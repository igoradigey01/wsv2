# 2026-11-14 — `skladX01_v0`: сделки поставщика и наполненная карточка

## Задача

Карточка поставщика повторяла карточку клиента только разметкой: блоки были
заглушками, потому что в API не было ни сделок поставщика, ни приходов, ни
выплат. Нужно довести её до симметрии: сделки поставщика в БД, блок
«КодСделки», вкладки «Принятый товар» / «Отданные деньги» с реальными данными.

## Решения

| Вопрос | Решение |
|---|---|
| Сделка клиента и сделка поставщика | разные, логически не связанные сущности: клиентская `Сделка` не менялась (`КлиентId NOT NULL`), для поставщика отдельная таблица `СделкаПоставщика` |
| Группировка при переносе | «поставщик + месяц даты прихода» = одна поставка; 125 документов прихода свернулись в 28 сделок |
| Связи | `Приход.КодСделкиПоставщика` и `Деньги.КодСделкиПоставщика` — отдельные колонки; клиентский `Деньги.КодСделки` не тронут |
| Защита от двойной привязки | `CK_Деньги_ОднаСделка`: нельзя заполнить обе колонки сделки одновременно |
| Выплаты поставщику | только чтение и пустое состояние; формы/POST нет. Демо-выплаты (40 строк) добавлены миграцией |
| Номер сделки поставщика | `P-000001` через `seq_НомерСделкиПоставщика` |
| Вкладки | свои, без Angular Material: `< 768px` — вкладки, `>= 768px` — блоки рядом |

## Что сделано

### БД (`db/sklad_v4_1`)

- Новый скрипт `alter-supplier-deals.sql` (идемпотентный) и обновлённые
  канонические `create-tables.sql`, `create-views.sql`, `create-triggers.sql`,
  `create-indexes.sql`, `verify-data.sql`, `database-schema.md`.
- `dbo.СделкаПоставщика` (`КодСделки` PK, `НомерСделки` UK, `ПоставщикId`,
  `Дата`, `Комментарий`, `Активна`, `ДатаСоздания`).
- `Приход.КодСделкиПоставщика`, `Деньги.КодСделкиПоставщика`,
  `CK_Деньги_ОднаСделка`, индексы по обеим колонкам.
- Триггеры: `TR_Приход_Проверка` (приход = закупка у того же поставщика),
  `TR_Деньги_Проверка` (выплата ссылается на поставщика сделки).
- Представление `vw_БалансСделкиПоставщика`: `Получено` из прихода,
  `Отдано` из выплат (`OperationType = 2` прибавляется, возврат `= 1`
  вычитается), `Долг = Получено − Отдано`.
- Демо-выплаты: `idx % 3` → 100 % / 40 % + 30 % / 55 % от суммы приходов
  сделки, поэтому долги получаются 0 / 30 % / 45 %. Итог по базе:
  получено 38 692 200, отдано 27 015 781.50, долг 11 676 418.50.
- Найдена ловушка: `uniqueidentifier` молча обрезает лишние символы, из-за
  чего суффиксы `01`/`02` в UETR схлопывались. Формат заменён на
  `C0000000-0000-0000-0001-{5 цифр поставщика}{6 цифр месяца}{1 цифра}`.
  Повторный запуск миграции не создаёт дублей (28 сделок / 40 выплат).
- Проверено: 154 клиентские сделки не изменились, приходов без сделки — 0.

### API (`SkladApi`)

- DTO: `СделкаПоставщикаDto`, `ПолученныйТоварDto`, `ОтданныеДеньгиDto`,
  `ПоставщикSummaryDto`.
- Репозитории: `СделкаПоставщикаRepository`, `ПолученныйТоварRepository`,
  `ОтданныеДеньгиRepository`, `ПоставщикRepository.GetSummaryAsync`.
- Эндпоинты:
  - `GET /api/suppliers/{id}/summary`
  - `GET /api/suppliers/{id}/deals`
  - `GET /api/suppliers/deals/{dealId}/products`
  - `GET /api/suppliers/deals/{dealId}/payments`
- `SupplierDealsEndpointTests` — 5 тестов; `dotnet test` — 23/23.

### Фронтенд (`apps/skladX01_v0`)

- `supplier.models.ts` — сырые `I…Api` с кириллицей + латинские модели
  `ISupplierSummary`, `ISupplierDeal`, `IReceivedGood`, `ISupplierPayment`.
- `supplier.service.ts` — `getSummary`, `getDeals`, `getDealProducts`,
  `getDealPayments` и функции маппинга.
- `supplier-detail.component.*`:
  - шапка со сводкой: получено, отдано, долг, сделок; предупреждение
    о переплате;
  - сворачиваемый блок «КодСделки» с таблицей сделок и итоговым долгом;
  - выбор сделки грузит её товар и деньги; на входе выбирается последняя;
  - на узком экране блоки «Принятый товар» и «Отданные деньги» — вкладки,
    на широком — рядом; фильтр «начиная» по дате и итоги в обоих блоках;
  - пустые состояния: «У поставщика нет сделок», «Выберите сделку»,
    «Нет принятого товара», «Нет отданных денег».
- Кнопка «Выплатить» остаётся disabled: выплата только для чтения.
