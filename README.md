## Выбор API-окружения (app `x01`)

Значение `production` в `apps/x01/src/environments/environment.ts` определяет, какой
файл `apps/x01/src/assets/app_environments/app_environments.*.json` загрузит приложение
(логика выбора — в `provideAppInitializer` в `apps/x01/src/app/app.config.ts`).

| `production` | Файл | `serverUri` (API) | `shopUri` (витрина) | `serverAuthUri` (identity) |
|---|---|---|---|---|
| `0` (default) | `app_environments.prod.json` | `https://s.x-01.ru/` | `http://localhost:5250/` * | `https://s.x-01.ru/` |
| `1` | `app_environments.local_vm.json` | `http://shop:8080/` | `http://localhost:5250/` | `http://shop:8080/` |
| `2` | `app_environments.local.json` | `http://localhost:5250/` | `http://localhost:5250/` | `http://localhost:5250/` |

Ключи:
- `serverUri` — базовый адрес API (`/api/...`);
- `shopUri` — адрес витрины (новый `ShopApi` на SkladDB, `/api/shop/...`);
- `serverAuthUri` — identity / аутентификация.

Текущий режим: **`production: 2`** → `app_environments.local.json` — все запросы идут на
`http://localhost:5250/` (ShopApi).

\* в `prod.json` `shopUri` пока заглушка (`http://localhost:5250/`) — при боевом деплое
заменить на реальный адрес ShopApi.

## Справочники номенклатуры (НСИ)

«Тип номенклатуры» отвечает за системную логику учёта (товар это или услуга),
а «Вид номенклатуры» — за бизнес-категорию и набор свойств товара.

| Параметр | Тип номенклатуры | Вид номенклатуры |
|---|---|---|
| За что отвечает | Как программа проводит позицию по складу и бухгалтерии. | Какие характеристики, единицы измерения и правила учёта у товара. |
| Кто настраивает | Зашит в программе (менять нельзя). | Создаёт и настраивает пользователь под свой бизнес. |
| Примеры | Товар, Услуга, Работа, Тара, Набор (комплект) | Плитные материалы, Обивочные материалы, Фурнитура, Готовая продукция |

### Для машины и для человека

- **Тип — для машины.** Программа решает, можно ли позицию потрогать и положить на склад.
  «Товар» → склад, остатки, списание себестоимости при продаже. «Услуга» (сборка, доставка) →
  без складских остатков, позиция попадает в акт выполненных работ.
- **Вид — для человека.** Бизнес-категория и набор свойств. Внутри одного типа «Товар» лежат
  и лист ЛДСП, и мебельная петля; чтобы не настраивать каждую карточку вручную, задают Вид:
  - «Плитные материалы» → Толщина, Длина, Ширина, Декор; ед.изм. — м² или лист;
  - «Обивочные материалы» → Ширина рулона, Плотность, Цвет; ед.изм. — пог. м.
  К виду обычно привязывают общие счета учёта, ставку НДС и шаблон ценника.
- **Группа — для человека.** Просто папка в каталоге для навигации и отчётов; на учёт не влияет.

### Виды номенклатуры (бизнес-категории)

Плитные материалы, Кромочные материалы, Обивочные материалы, Фурнитура, Крепёж,
Наполнители, Клеи и ЛКМ, Стёкла и зеркала, Упаковка, Готовая продукция, Услуги, Прочее.

### Каталог — это иерархия групп (папок)

Каталог (навигация и витрина) задаётся справочником `ГруппаНоменклатуры` (поле `РодительId`):
- `РодительId = NULL` → корневой раздел;
- остальные — подкаталоги по `РодительId`.

Рекомендуемые корневые папки: Материалы, Готовая продукция, Услуги.
Позиция попадает в папку по `Номенклатура.ГруппаId`.

### Как добавить подкаталог

Подкаталог = группа с `РодительId` = id родительской папки.

1. API: `POST /api/references/groups`, тело `{ "название": "Шкафы", "родительId": 2 }`.
2. UI `/admin/groups`: пока создаёт только корневую группу (без выбора родителя) —
   подкаталоги через API/SQL.
